## Conclusion

The request format is now correct: the failures reproduce with genuine Codex-generated traffic. Switching from T2 to VIP Singapore, changing the reasoning effort, and selecting another advertised 6-series model do not help.

The failure occurs inside FreeModel after Codex reaches its inference endpoint. The available generic 503 response does not distinguish among an exhausted model pool, account quota/concurrency restriction, or regional routing outage. There is no response request ID or `Retry-After` header to identify a specific incident.

No active configuration change can solve the observed 503 without switching to a different provider or FreeModel restoring capacity for this account/model pool.
